# Аудит переносимости: сколько кода переживёт переезд в SaaS

> Проведён **12.10.2026** по каркасу v0.7 статическим анализом:
> разбор на функции, поиск обращений к Apps Script API, построение графа вызовов
> и транзитивного замыкания. Методика описана в конце — цифры воспроизводимы.

## Короткий ответ

**Код — наполовину. Знание — целиком.**

```
всего:  93 функции, 2 933 строки кода функций
        (в файлах 2 941 строка: 8 строк — заголовки вне функций)

переезжает в SaaS:  50 функций, 1 319 строк   (45%)
пишется заново:     43 функции, 1 614 строк   (55%)
```

Но эти 55% — не потеря. Это **слой, который в SaaS обязан быть другим**:
таблица → база данных, меню → веб-интерфейс, триггеры → очередь задач.
Писать их «переносимыми» было бы ошибкой проектирования.

---

## 1. Что переезжает почти без правок

| Блок | Функций | Строк | Переезжает |
|---|---|---|---|
| **Клиент Seller API** | 16 | 419 | **16/16 — весь** |
| **Клиент Performance API** | 11 | 274 | **11/11 — весь** |
| **Парсер CSV-отчёта Performance** | 8 | 285 | **8/8 — весь** |
| Доменные мелочи (`ratioToPercent_`, `pickSku_`, `mskRange_`, шапки) | 7 | 121 | **7/7** |
| Очередь и состояние (`propList*`) | 3 | 31 | 3/3 |
| **Итого ядро** | **50** | **1 319** | **45%** |

**Это самое дорогое.** Внутри:
- точные формы запросов, оплаченные HTTP 400 на живом аккаунте;
- обход мёртвого хоста `performance.ozon.ru` с ручным следованием за 307;
- определение CSV против ZIP по сигнатуре байтов (`0x50 0x4B`);
- словарь колонок отчёта Performance, включая «Продажи в продвижении, ₽»;
- волны по 3×10 кампаний с накоплением состояния и предохранителем по времени;
- пагинация четырьмя разными способами (`last_id`, `cursor`, `offset`, чанки)
  — по способу на каждый метод, как того требует Ozon.

Переписать это с нуля — повторить все те же ошибки.

---

## 2. Что пишется заново

| Блок | Функций | Строк | Во что превращается |
|---|---|---|---|
| Хранение в таблице (`sheet_`, `ss_`, `ensureSheets`, `addProblems_`, …) | 13 | 358 | Репозитории поверх Postgres |
| UI, меню, триггеры (`onOpen`, `menu*`, `installTriggers`, …) | 22 | 174 | Веб-интерфейс + планировщик |
| Оркестрация синков (`syncFact`, `syncSales`, `syncDrr`, `diagCommission`, …) | 10 | 1 082 | Воркеры очереди задач |
| **Итого** | **45** | **1 614** | **55%** |

**Оркестрация — самый большой кусок (1 082 строки), и это правильно.**
Но её *логика* уже написана, протестирована и задокументирована: какие методы
в каком порядке вызывать, как обходить лимиты, как возобновлять после обрыва,
когда данным можно верить. Переписывается plumbing, а не решения.

## 3. Цена переноса ядра — четыре адаптера

Чтобы 45% кода стали переносимыми, нужно заменить ровно четыре вещи.
В Apps Script они сейчас зашиты напрямую, в SaaS становятся внедряемыми:

| Apps Script | Замена | Трудозатраты |
|---|---|---|
| `UrlFetchApp.fetch` (**2 места**) | `fetch` / axios | час |
| `PropertiesService` (**7 мест**) | `process.env` / secret manager | час |
| `Utilities.formatDate`, `Utilities.sleep` (**38 мест**) | `dayjs`, `setTimeout` | час |
| `Session.getScriptTimeZone()` (**8 мест**) | константа `'Europe/Moscow'` | минуты |
| `logMsg_` → `LOG_SINK_` (по умолчанию лист через `sheetLogSink_`) | консоль / Pino / БД | **главный шов; seam реализован в v0.8** |

**`SpreadsheetApp` — 8 обращений, `ScriptApp` — 6.** Именно они, а не HTTP,
держат код в таблице.

### Главный шов — логирование

Сейчас цепочка выглядит так:

```
sellerFetch_  →  logMsg_  →  LOG_SINK_  →  sheetLogSink_ (по умолчанию)  →  sheet_  →  SpreadsheetApp
```

Раньше `logMsg_` напрямую вызывал `sheet_`, поэтому вызовы API тянули за собой
Google Sheets. В v0.8 `logMsg_` обращается только к `LOG_SINK_`; значение по
умолчанию — `sheetLogSink_`, сохраняющий прежний лист, формат и ротацию. Sink
можно заменить без изменений клиентов API. Тест `tests/log_sink.js` проверяет,
что подменённый sink не создаёт и не вызывает лист.

## 4. Методика (чтобы цифры можно было перепроверить)

1. Файлы `.gs` склеиваются, разрезаются по `^function\s+\w+` — получаем 93 тела.
2. **Прямая привязка** — регулярный поиск `\b<NAMESPACE>\s*\.` по списку:
   `SpreadsheetApp`, `UrlFetchApp`, `PropertiesService`, `ScriptApp`, `Session`,
   `Utilities`, `Blob`, `Logger`, `LockService`, `CacheService`, `MailApp`, `DriveApp`.
3. **Граф вызовов** — `\b(\w+?)\s*\(` ∩ множество имён функций.
4. **Транзитивное замыкание** — функция считается привязанной, если привязана
   сама или вызывает привязанную.
5. **Адаптеры исключаются** из графа: их собственные привязки игнорируются,
   и вызовы их не заражают. Так моделируется замена инфраструктуры.

### Ошибки методики, которые я сам сделал и исправил

Записываю, потому что они дают противоположные выводы:

- **Первый прогон дал «57 функций — чистый JS».** Неверно: проверялись только
  *прямые* обращения. `sheet_` попала в «чистые», потому что вызывает `ss_()`,
  а не `SpreadsheetApp` напрямую. Только транзитивное замыкание даёт честную цифру.
- **Второй прогон дал «14 функций, 13%».** Пессимистично: связывающими посчитаны
  `UrlFetchApp`, `PropertiesService`, `Utilities`, `Session` — а они заменяются
  шимом в 40 строк. Разделять надо на «исчезнет совсем» и «заменится адаптером».
- **Третий прогон дал «0 добавленных функций».** Логика была обратной: адаптеры
  я *пометил привязанными*, а их надо *исключать из графа*.

Итоговая корректная цифра — **50 функций / 1 319 строк / 45%**.

## 5. Что переносится помимо кода

Код — меньшая часть ценности. Вот что реально не придётся добывать заново:

| Актив | Где лежит | Почему дорог |
|---|---|---|
| **Карта API с тупиками** | `docs/API-MAP.md` | 6 мёртвых методов с датами отключения, 4 разных способа пагинации, разница форм FBO/FBS |
| **Валидатор тел запросов** | `tests/schema.js`, `tests/negative.js`, `schema/ozon_paths.json` | Ловит HTTP 400 до отправки. На теле v0.6 находит 5 запрещённых полей + превышение лимита |
| **Правила качества данных** | `docs/DATA-MODEL.md` §2, `docs/DECISIONS.md` B15/D1 | «Помечать, а не молча считать» — сформулировано пользователем |
| **Формулы с round-trip** | `core/unit-economics.js` | 960 комбинаций, расхождение < 1e-9 |
| **Пороги доверия к замеру** | `core/commission.js` | Почему нельзя подставлять скидку при 2 артикулах |
| **Парсер CSV Performance** | `appsscript/02_OzonPerformance.gs` | Словарь колонок, BOM, строка «Всего», имя файла в ZIP |
| **Реестр отклонённого** | `docs/DECISIONS.md` §G | 9 направлений, которые не надо предлагать повторно |

---

## 6. Что НЕ переносится ни при каких условиях

1. **Apps Script как платформа.** Триггеры, меню, `Script Properties`, лимит
   6 минут на выполнение, отсутствие нормального HTTP-клиента. В SaaS это
   не «переносится», а заменяется полностью.
2. **Google Sheets как хранилище.** Перезапись листа целиком не даёт истории
   и не масштабируется на мультитенантность.
3. **Привязка к одному аккаунту через `Script Properties`.** В SaaS ключи
   каждого тенанта хранятся зашифрованными в БД, с отдельным OAuth-потоком.
4. **Однопоточность.** Волны по 3×10 кампаний с предохранителем 4,5 минуты —
   это обход лимита платформы. В SaaS задачи живут в очереди и ограничений
   по времени выполнения нет, остаётся только уважать лимиты самого Ozon.
