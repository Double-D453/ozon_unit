# Ozon Unit — юнит-экономика продавца Ozon

Автоматический расчёт наценки по каждому SKU продавца Ozon: фактические тарифы,
комиссии, логистика и расходы на рекламу подтягиваются из API, а обратный расчёт
даёт целевую цену и «ограничение для акций».

**Текущая форма:** каркас на Google Apps Script (v0.7) поверх Google Таблицы.
**Целевая форма:** мультиарендный SaaS. Что переносится и в каком порядке —
[`docs/ROADMAP-SAAS.md`](docs/ROADMAP-SAAS.md).

> Продолжаете работу с этим проектом? Начните с [`HANDOVER.md`](HANDOVER.md).

---

## Быстрый старт

```bash
# доменное ядро — 80 проверок, зависимостей нет
node core/core.test.js

# каркас Apps Script — 8 тестов
cd tests && ./prepare.sh && TESTFILE=schema.js node all.js
```

Ни один тест не обращается к сети и к Google — всё на моках и на локальной
копии официальной схемы Ozon. То же одной командой: `npm test`.

## Три вещи, которые стоит знать до чтения кода

**1. Ozon отвечает HTTP 400 на лишнее поле в теле запроса.** Не игнорирует —
отклоняет. А ошибка выглядит так же, как «нет данных» или «нет прав». Поэтому
в репозитории есть валидатор `tests/schema.js`: он сверяет тела запросов с
официальной схемой **до отправки**. На теле предыдущей версии он находит
5 запрещённых полей плюс превышение лимита — и это была причина молча пустого
листа с комиссией. Проверка закреплена как постоянный тест `tests/negative.js`.

**2. Расходов на рекламу в аналитике продаж не существует.** Метрики `adv_sum_all`
нет в схеме Ozon — 0 вхождений. ДРР собирается из двух разных API: числитель из
Performance, знаменатель из `/v1/analytics/data`. Это не неудобство, а конструкция.

**3. Для фактической комиссии важен правильный знаменатель.** Сырой аудит
18 ответов API подтвердил, что `standard_fee` соответствует комиссии от
`seller_price_per_instance × delivery_commission.quantity`. Поле `amount` —
другая ценовая база, поэтому деление на него и давало значения выше 100%.
Начисление сверяется отдельно с учётом бонусов и коинвестиций; B14 аудитом
не калибруется.

## Безопасность

API-ключи Ozon хранятся **только в `Script Properties`**, никогда в таблице и
никогда в репозитории. Ранее ключи хранились открыто и были перевыпущены —
это требование пользователя, а не рекомендация.

Функция `deleteAllProperties()` в коде запрещена: она стирает ключи вместе с
накопленным состоянием кампаний.

**В Ozon сейчас ничего не отправляется.** `previewExport` — заглушка, показывающая,
что было бы отправлено. Запись цен включается отдельным решением на этапе Э5.
